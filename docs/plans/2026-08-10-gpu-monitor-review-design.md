# GPU 价格监控项目审计与界面统一设计

## 目标与边界

本轮改动保留现有 Flask + 原生 HTML/CSS/JavaScript 架构、SQLite 数据和四种采集模式，不引入前端框架，也不改变用户已有登录 profile。目标是修复可复现的逻辑、并发、数据一致性与前端安全问题，并把目前纵向堆叠的深色页面整理为一致、清晰、可响应的“GPU 遥测工作台”。项目目录当前不是 Git 仓库，因此不初始化仓库、不创建提交，也不触碰 `.chrome_profile/`、`.sessions/` 和现有用户数据。

## 架构与数据流

后端继续由 `app.py` 提供 JSON API，`crawler.py` 负责采集生命周期与通道降级，`database.py` 负责当前商品和价格历史，`gpus.py` 负责型号识别，`recommend.py` 与 `charts.py` 提供衍生数据。修复重点是让生命周期成为明确状态机：只有运行中的任务可以暂停/恢复；异常或自然退出一定释放运行标记；停止和轮询等待可中断，避免旧线程与新线程重叠。数据库清理统一经过带锁的数据层，同时清理当前价与历史价。型号识别按最长、最具体关键词匹配，避免 Ti/Super 被基础型号判为冲突；自定义型号直接使用其推断出的系列与代次。

前端保留现有 API 和元素 ID 以降低回归风险，但把初始化改为单一、可等待的流程，避免“设置先返回、型号后返回”造成选择状态丢失。所有来自采集页面、数据库或用户输入的文本在进入 `innerHTML` 前转义，外链只允许 HTTP/HTTPS。请求层统一检查网络错误、HTTP 状态和 JSON 响应。状态轮询只更新运行态；真实商品数、覆盖型号和行情数据由数据接口统一驱动，避免状态接口每四秒把统计卡覆盖为内存计数。

## 视觉与组件

视觉采用石墨黑、雾蓝和青绿信号色，强调“硬件遥测”而非霓虹电竞。统一颜色、圆角、阴影、间距、字号、输入框、按钮、标签、空状态和焦点环；标题使用 Bahnschrift / 微软雅黑组合，价格和运行数值使用紧凑数字样式。页面增加工作台式头部与快捷导航，核心状态、关注行情和采集控制优先进入首屏；设置、登录和 API 配置形成一致的操作区；推荐、统计、图表和数据表形成分析区。桌面使用 12 列网格，窄屏回落为单列；表格保持横向滚动，按钮和输入在手机宽度下铺满。动画仅用于状态与首屏进入，并遵守 `prefers-reduced-motion`。

## 错误处理与验证

API 对无效模式、阈值、型号、趋势参数返回明确的 4xx JSON；前端展示错误并恢复按钮状态，不静默吞掉关键操作失败。API secret 不再回传明文，密码输入使用 `type=password`，空白 secret 更新表示保留已有值。验证覆盖 Python 编译、标准库单元测试、Flask test client、JavaScript 语法检查，以及本地浏览器的桌面/移动截图、控制按钮状态、筛选与无控制台错误检查。不会在测试中发起真实平台采集或修改现有 `prices.db`。
