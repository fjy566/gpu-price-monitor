# GPU 价格监控中心：产品化与可用性设计

## 目标

把当前工具从“需要理解内部工作方式才能使用”调整为“普通用户按页面提示即可完成登录、选型、采集和判断数据是否可信”。继续采用本地 Flask + Playwright + SQLite 单体结构，不引入部署成本高的服务。

## 方案选择

评估三个方向：只修已知缺陷、整体重构、稳健增强。只修缺陷无法解决首次使用和状态解释问题；整体重构会放大采集回归风险。采用稳健增强：保留可靠的数据与采集边界，集中改善运行状态机、错误恢复、数据新鲜度、安全默认值和前端信息架构。

## 用户流程

页面首先展示三个准备状态：采集型号、闲鱼登录、历史数据。点击开始时自动保存当前型号和过滤阈值，避免“页面选了但后台仍用旧设置”。登录入口负责启动浏览器并打开闲鱼登录页。每轮结束显示成功、无数据和失败型号，允许只重试失败型号。

价格库增加更新时间范围筛选和相对时间，避免把数日前的旧商品误认为刚采集结果。服务断开时给出可见提示，恢复后自动清除。

## 后端与安全

- 恢复持久化轮次和上次采集时间。
- 为每轮建立结构化结果摘要，并支持失败型号重试。
- 暂停信号进入页面批次回调，使长型号任务也能暂停。
- 浏览器未运行时切换模式只保存配置，不启动后台浏览器。
- 默认只接受本机请求；远程访问必须显式开启。
- 调试接口默认关闭，且即使开启也只允许本机访问。
- 校验型号、历史查询和诊断关键词的长度与字符。
- Cookie、会话、数据库和日志继续由 `.gitignore` 隔离，提交前扫描 Git 可达对象。

## 视觉与交互

延续深色“市场遥测台”风格，用同一套间距、圆角、控件高度和状态色。新增准备状态条、轮次摘要、数据新鲜度标签和模式选择器，不引入新的视觉体系。移动端将步骤条和操作区改为单列，按钮保留足够触控面积。

## 验证

覆盖单元测试、Flask 接口测试、JavaScript 语法、Python 编译、数据库完整性、桌面/移动视觉截图、关键用户流程和 Git 敏感信息扫描。任何失败都在推送前修复。
